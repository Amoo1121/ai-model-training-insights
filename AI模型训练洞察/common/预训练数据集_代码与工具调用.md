## 一、代码预训练数据集：The Stack

**来源**: [BigCode Project](https://www.bigcode-project.org/)  
**论文**: "The Stack: a 3.5TB dataset of code with permissions for training"  
**HuggingFace**: [bigcode/the-stack](https://huggingface.co/datasets/bigcode/the-stack)

### 1. 数据来源

| 属性 | 说明 |

### 3. 关键处理步骤详解

#### Step 1: 许可过滤
```python
# 接受的许可类型（部分）
ACCEPTED_LICENSES = [
    "apache-2.0",
    "bsd-2-clause",
    "bsd-3-clause",
    "gpl-2.0",
    "gpl-3.0",
    "lgpl-2.1",
    "mit",
    "mpl-2.0",
    "cc0-1.0",
    # ... 共 30+ 种
]
```

#### Step 2: 去重策略
| 方法 | 说明 |
|------|------|
| Exact Deduplication | SHA256 哈希精确匹配，移除完全重复文件 |
| MinHash LSH | 近似去重，相似度 > 0.8 的文件保留一份 |
| Near-duplicate Detection | 检测代码模板相同的文件（如 scaffolding） |

#### Step 3: 质量过滤规则
```
过滤条件：
- 平均行长度 > 200 characters
- 最大行长度 > 10000 characters  
- 字符集异常（非 UTF-8）
- 含有明显自动生成标记（"Generated by", "Created automatically"）
- 注释比例异常低
- 空行比例 > 50%
```

### 4. 训练格式

**原始格式**（用于预训练）：
```json
{
  "content": "def hello_world():\n    print('Hello, World!')",
  "language": "python",
  "repo": "example/repo",
  "path": "hello.py",
  "license": "mit",
  "sha": "abc123..."
}
```

**分词处理**：
- 使用 tokenizer 将代码切分为 token 序列
- 代码专用 tokenizer（如 StarCoder 使用的 tokenizer）

### 3. 核心处理步骤详解

#### Step 1: 自监督工具调用数据生成

**核心思想**：让 LLM 自己学习何时、如何调用工具，而不需要人工大量标注。

```python
# 输入：原始文本
input_text = "What is 1257 * 892?"

# 提示 LLM 生成工具调用
prompt = f"人类的输入: {input_text}\n\n\
你是一个助手，需要决定是否使用工具。\
以下是可用的工具:\n\
- calculator: 计算数学表达式\n\n\
基于输入，决定是否调用工具，如果调用，返回:\
[TOOL_CALL]calculator|1257 * 892[/TOOL_CALL]"

# LLM 生成的回复可能包含工具调用
```

## 三、处理流程对比

| 维度 | The Stack (代码) | Toolformer (工具调用) |
|------|-----------------|----------------------|
| **数据来源** | GitHub 公开仓库 | 多源文本 + API |
| **处理方式** | 规则过滤 + 去重 | LLM 自生成 + 过滤 |
| **人工标注** | 无 | 极少（仅提供 API 演示） |
| **核心挑战** | 许可合规、去重 | 工具调用质量评估 |
| **训练目标** | Next Token Prediction | 工具调用决策学习 |
| **数据规模** | 3.5TB, 多种语言 | 数十K 级别的工具调用样本 |

## 四、关键洞察

### 1. 代码数据处理要点
- **许可合规是前提**：必须确保代码许可允许用于模型训练
- **去重很重要**：代码中样板/模板代码比例高，去重能显著提升数据效率
- **质量过滤多层次**：从文件级别到行级别多层过滤

### 2. 工具调用数据处理要点
- **自监督是关键**：无需大量人工标注，LLM 可自主生成工具调用样本
- **执行验证不可少**：工具调用必须真正执行，验证结果有效性
- **过滤阈值需精心设计**：太低会引入噪声，太高会损失数据

### 3. 两种范式对比
- **代码**：数据量大、来源稳定、但需要复杂的许可处理和质量过滤
- **工具调用**：数据量小（相对）、但需要设计好的 API 接口和评估指标
